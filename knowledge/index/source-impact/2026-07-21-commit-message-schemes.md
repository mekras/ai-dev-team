# Влияние схем сообщений коммитов на продукт

## Источники и границы

Проверены 2026-07-21:

- `CCMT`: Conventional Commits 1.0.0;
- `GTMJ`: спецификация Gitmoji;
- `PGIT`: раздел `Commit Guidelines` книги Pro Git;
- `GITD`: официальная документация Git по шаблонам и hooks.

Дополнительное основание адаптации: `PGIT-002` рекомендует английское
повелительное наклонение, а правило русских сообщений коммитов навыка `ru-lang`
требует для русского заголовка краткое страдательное причастие.

Область аудита: настройка целевого проекта, рабочие правила для агентов,
подготовка сообщений коммитов, требования и постоянные проверки продукта.

## Находки

### Severity: High — проекту нужна одна выбранная схема

Документ: `ait-setup`, `AGENTS.md` целевого проекта и файл состояния.

Источник: `CCMT-001`, `CCMT-003`, `GTMJ-001`, `PGIT-001`, `PGIT-002`.

Класс: новое существенное сведение.

Факт источника: три источника задают разные формы сообщения и разные цели.

Область применения: целевые проекты с Git.

Вывод: одновременное применение вариантов без отдельного профиля создаёт
расхождение истории и проверок.

Статус переноса: `apply_now`.

Что сделать: добавить выбор в `ait-setup`, сохранять его в
`setup.commit_messages` и закреплять как рабочее правило проекта.

### Severity: High — выбранную схему нужно применять перед коммитом

Документ: новый навык `ait-commit-messages`.

Источник: `CCMT-001`, `GTMJ-001`, `PGIT-001`, `PGIT-002`.

Класс: новое существенное сведение.

Факт источника: каждая схема задаёт наблюдаемые признаки сообщения.

Область применения: подготовка и проверка нового сообщения коммита.

Вывод: одной служебной записи в файле состояния недостаточно для обычной
предметной задачи агента.

Статус переноса: `apply_now`.

Что сделать: добавить навык подготовки и проверки сообщения, а выбранную схему
дублировать только как необходимое рабочее правило в инструкциях проекта.

### Severity: Medium — Gitmoji требует дополнительного выбора

Документ: `ait-setup` и `ait-commit-messages`.

Источник: `GTMJ-002`.

Класс: новое существенное сведение.

Факт источника: Gitmoji допускает Unicode и короткие коды.

Область применения: проекты, выбравшие Gitmoji.

Вывод: без фиксации представления агенты могут создавать неоднородную историю.

Статус переноса: `apply_now`.

Что сделать: после выбора Gitmoji отдельным вопросом закрепить
`setup.commit_messages.emoji_format`.

### Severity: Medium — экосистема влияет на стоимость внедрения

Документ: `PDR-0001`, `PDR-0002`, `PDR-0003`.

Источник: `CCMT-004`, `CCMT-005`, `GTMJ-003`, `GTMJ-004`, `PGIT-003`,
`GITD-001`, `GITD-002`.

Класс: новое существенное сведение.

Факт источника: схемы различаются по готовым специализированным средствам и
совместимости со встроенными средствами Git. Gitmoji CLI отдельно синхронизирует
словарь с репозиторием. Официальные страницы дают лишь косвенные признаки
распространённости, но не сопоставимую долю применения.

Область применения: выбор схемы для включения в продукт.

Вывод: в PDR нужно отдельно показать влияние готовых средств и подтверждённых
примеров применения на порог входа, не выдавая их за измерение рынка.

Статус переноса: `apply_now`.

Что сделать: дополнить достоинства и риски кандидатов проверяемыми сведениями об
инструментальной поддержке, сопровождении словаря и границах данных о
распространённости.

### Severity: High — форма Pro Git зависит от языка проекта

Документ: `PDR-0003`, `ait-commit-messages`, `ait-setup` и рабочее правило
целевого проекта.

Источник: `PGIT-002` и правило `ru-lang`.

Класс: противоречие.

Факт источника: Pro Git рекомендует английское повелительное наклонение, а
`ru-lang` требует описывать завершённый результат кратким страдательным
причастием и запрещает эту форму в русском сообщении.

Область применения: проекты, которые пишут сообщения коммитов по-русски.

Вывод: буквальный перенос английской формы создаёт противоречащие друг другу
рабочие правила и повышает риск неоднородной истории.

Статус переноса: `apply_now`.

Что сделать: использовать нейтральное значение настройки `pro-git`; для русского
заголовка применять форму результата из `ru-lang`, а исходную рекомендацию
сохранять для английского языка.

## Статус решений

Приняты все три рассмотренные схемы:

- `PDR-0001` — Conventional Commits, принято;
- `PDR-0002` — Gitmoji, принято;
- `PDR-0003` — рекомендации Pro Git с языковой адаптацией, принято.

Поддержка Conventional Commits, Gitmoji и адаптированных рекомендаций Pro Git
соответствует принятым решениям.

## Ограничения

Автоматические проверки служб Git зависят от стека целевого проекта. Продукт
закрепляет переносимую процедуру агента, но не устанавливает один инструмент
проверки для всех проектов.

Сопоставимых данных о доле применения трёх схем не найдено. Наличие официальных
средств, публичного словаря и именованных пользователей учитывается только как
косвенный признак, а не как рейтинг распространённости.
