# Типы и ограничения схемы SQLite

Проверены официальные страницы SQLite о `CREATE TABLE`, типах, внешних ключах
и таблицах `STRICT`. Нормализованы только положения, нужные для физического
отображения модели данных.

## Состав определения таблицы

Определение таблицы может фиксировать столбцы, объявленные типы, значения по
умолчанию, первичный ключ, уникальность, отсутствие `NULL`, проверочные
условия, внешние ключи и вычисляемые столбцы. Ограничения должны находиться в
схеме, если целостность нельзя безопасно оставить только коду приложения.

Внешний ключ поддерживает отношение существования между таблицами. Допустимость
`NULL` регулируется отдельно через `NOT NULL`.

## Особенность типов SQLite

В обычных таблицах SQLite тип связан прежде всего со значением, а объявленный
тип столбца определяет склонность преобразования. Таблицы `STRICT` требуют тип
для каждого столбца и отвергают значения, которые нельзя без потерь привести к
нему. Поэтому перенос модели в SQLite должен явно выбирать обычный или строгий
режим и не приписывать обычным таблицам статическую типизацию других СУБД.

Проверяемые краткие фрагменты:

- `constraints on the table content`
- `uses dynamic typing`
- `Every column definition must specify`
- `foreign key constraint`
- `unlike most SQL databases`

## Ограничения

Эти правила относятся к физической схеме SQLite. Они не определяют смысл
предметной модели и не переносятся автоматически на другие СУБД.
