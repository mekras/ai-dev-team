## Слой управления применением ИИ

Фундаментом продукта является [коллекция навыков для управления применением
ИИ][ai-agent-supervisor].

Этот слой задаёт границы самостоятельных действий, точки решения человека и
проверку готовности результата.

## Корпус знаний проекта

Продукт устанавливает навыки для учёта источников, нормализации, извлечения
утверждений, анализа, проверки и оценки влияния изменений. Формат и порядок
работы описаны в [пользовательском руководстве](../user/knowledge.md).

## Гипотезы и решения

Если сведений недостаточно для обоснованного требования, продукт помогает
зарегистрировать проверяемую гипотезу и по явному решению пользователя
использовать её как временное основание ограниченной работы. Гипотеза не
выдаётся за требование или установленный факт. Её запись сохраняет область
работы, риски, свидетельства и вывод.

Значимый выбор по гипотезе оформляется отдельным решением без автоматического
подтверждения гипотезы. Когда свидетельств достаточно для требования, результат
проходит обычные анализ, проверку и согласование требований.

## Граф влияния проекта

Настройка создаёт единый направленный граф зависимостей проектных частей. После
изменения продукт находит все части, которые оно может затронуть, показывает
путь до каждой из них и назначает профильную проверку. Профильный навык
устанавливает, нужна ли правка. Само попадание части в результат анализа не
означает автоматическое изменение.

Один граф применяется в обычных задачах, при работе с требованиями и корпусом
знаний, а также во время полной проверки репозитория.

## Наблюдение за реальными сессиями

Продукт умеет качественно анализировать новые завершённые части локальных
сессий Codex и Claude Code. Обычный запуск не требует каждый раз выбирать
сессию и не перечитывает всю историю. Результат остаётся свободным отчётом по
фактическим находкам, а не обязательной формой с заполненными догадками полями.

Парный навык проверяет отчёт другого пользователя как недоверенное наблюдение.
Он отделяет факты от трактовок, сверяет существенные утверждения с текущим
продуктом и только затем выбирает профильный маршрут.

Сырые журналы не собираются централизованно. Выбранное содержимое доступно
активной модели клиента, поэтому применимость зависит от правил проекта,
поставщика модели и допустимости обработки данных.

## Скрытый локальный слой знаний (тайные знания)

Продукт поддерживает локальные знания проекта для агента: `AGENTS.local.md`,
`rules.local/` и похожие неотслеживаемые материалы. Этот слой нужен для
сведений, которые помогают агенту работать точнее, но не должны попадать в VCS.
