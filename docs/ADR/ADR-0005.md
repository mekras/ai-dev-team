# ADR-0005: Ресурсное планирование автономного прохода

Статус: Принято
Дата: 2026-07-31
Участники: владелец проекта, разработчик

## Контекст

Тяжёлое медиа может временно не помещаться на диске. Остановка всего прохода
при первой такой задаче оставляет необработанными другие готовые материалы.
Отдельные шаги загрузки, расшифровки и очистки также повышают риск потерять
состояние между сеансами.

## Рассмотренные варианты

- Остановить проход на первой недоступной очереди. Вариант прост, но снижает
  пропускную способность.
- Игнорировать оценку ресурсов. Вариант продолжает работу, но может заполнить
  диск и оставить частичные файлы.
- Планировать готовые очереди по доступным ресурсам и объединить жизненный цикл
  временного медиа в возобновляемую операцию.

## Решение

Исполнитель стадии может объявить минимальный резерв и ожидаемый пиковый расход
диска. Планировщик откладывает неподходящую очередь, продолжает другие готовые
очереди первичного контура и использует `paused_resources` только при
отсутствии любой исполнимой автоматической задачи.

Медиа допускается обрабатывать одним составным исполнителем: получить
временный файл, расшифровать, проверить непустой результат, записать состояние
подэтапов и удалить только подтверждённый временный файл. Повтор продолжает
незавершённый подэтап без дублирования результата.

## Последствия

- Одна тяжёлая задача не блокирует весь корпус.
- Ресурсная пауза получает конкретные причины по очередям.
- Временное медиа удаляется раньше и безопаснее.
- Проектные исполнители отвечают за оценку пикового расхода и возобновляемость
  составной операции.

## Проверка

Контроллер проверяется сценарием недоступной по диску ранней очереди и
исполнением более поздней готовой очереди. Договор расшифровки проверяет
порядок подтверждения результата и очистки.

Решение принято владельцем проекта в диалоге 2026-07-31. Независимая проверка
классом усиленной проверки подтвердила границу первичного контура и выявила
старое имя состояния внешнего ожидания в архитектурной диаграмме. Диаграмма
приведена к каноническому `waiting_external`.

## Условие пересмотра

Решение пересматривается, если очереди потребуют явного графа зависимостей
вместо текущего порядка готовых стадий или оценка ресурсов на уровне стадии
окажется недостаточной.
