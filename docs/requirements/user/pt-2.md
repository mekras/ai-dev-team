# ПТ-2

[К списку требований](../../requirements.md)

## Требование

Заказчик может описывать цели, проблемы и ожидаемый результат в свободной форме,
без предварительной подготовки спецификации требований.

Для начала работы достаточно описать хотя бы один из трёх элементов: цель,
наблюдаемую проблему или ожидаемый результат. Шаблон, типы требований, полный
набор критериев успеха, перечень заинтересованных лиц и исключений не являются
предварительным условием.

Продукт принимает свободный запрос как исходный материал, отделяет
подтверждённые сведения от допущений и открытых вопросов, постепенно уточняет
пробелы и возвращает требования-кандидаты. Он может остановить следующий шаг на
одном вопросе, только если без ответа нельзя безопасно продолжить. Массовая
обязательная анкета до начала содержательной работы недопустима.

Свободный запрос не становится утверждённой спецификацией: его содержание
проходит выявление, проверку и отдельное принятие.

## Основание

Концепция; корпус знаний — `SREQ-001`, `SREQ-002`, `SREQ-028`, `SREQ-029`,
`SREQ-031`; решение владельца; `ФТ-11`.

## Реализация

- README предлагает описать цель, проблему или ожидаемый результат обычными
  словами.
- `ait-req-elicitation` принимает такой запрос без предварительной анкеты и
  ведёт постепенное выявление.
- Результат выявления остаётся черновиком требований-кандидатов с основаниями и
  статусами.

## Проверка

- Сценарий
  `ait-req-elicitation-requirements-elicitation-result-free-form-request`
  проверяет начало работы при неполном свободном описании.
- Отрицательный контроль отвергает требование профессиональной спецификации или
  обязательной анкеты до выявления.
- Полная проверка выполняется командой `apm run tests`.
