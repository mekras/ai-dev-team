# ПТ-4

[К списку требований](../../requirements.md)

## Требование

Результат считается готовым не по факту завершения работы ИИ, а по возможности
заказчика его проверить и принять.

Завершение ответа, команды, изменения файлов или автоматических тестов само по
себе не означает ни готовности к приёмке, ни принятия результата.

Для статуса `готов к приёмке` заказчик получает:

- результат или точное местонахождение артефакта;
- критерии приёмки;
- выполненные проверки и их проверяемые результаты;
- пропущенные или проваленные проверки;
- ограничения и остаточные риски;
- явный выбор: принять результат или вернуть на доработку.

Статус `принят` появляется только после явного решения заказчика. Провал
обязательной проверки означает `нужна доработка`; зависимость от недоступного
решения, данных или внешнего состояния — `заблокирован`. Частично проверенный
результат не выдаётся за готовый без согласованного исключения и принятия
остаточного риска.

Промежуточный результат можно передать следующей роли без приёмки заказчиком, но
его статус и границы проверки должны быть явными. Такая передача не заменяет
приёмку итогового результата задачи.

## Основание

Фундамент (приёмка результата); корпус знаний — `SCSU-032`, `SCXP-024`; `ПТ-1`;
решение владельца.

## Реализация

- Менеджер проекта формирует пакет приёмки и различает готовность, принятие,
  доработку и блокировку.
- Клиентская инструкция сохраняет эту границу во всех поддерживаемых клиентах.
- Зависимость `ai-agent-supervisor` предоставляет навык
  `ai-work-result-evaluation` для проверки результата по критериям и проверочным
  случаям.

## Проверка

- Сценарий `ait-routing-routing-result-handoff-for-acceptance` проверяет пакет
  приёмки и запрещает считать успешные тесты решением заказчика.
- Валидатор проверяет правила менеджера, клиентскую инструкцию, сценарий и
  наличие навыка проверки результата в установленной зависимости.
- Полная проверка выполняется командой `apm run tests`.
