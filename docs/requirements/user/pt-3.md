# ПТ-3

[К списку требований](../../requirements.md)

## Требование

Заказчик явно выбирает клиентский инструмент (`claude` или `codex`); подключение
сразу для всех целей по умолчанию не используется.

Первичная установка содержит ровно одну цель `--target claude` или
`--target codex`. Значение `all`, список целей и команда без `--target` не
являются пользовательским способом подключения.

Если настройка не может однозначно восстановить выбор из явной команды или
конфигурации, продукт задаёт один блокирующий вопрос. Наличие каталогов обоих
клиентов не считается согласием настроить оба: они могут остаться от прежней
установки или появиться при проверке пакета.

Требование относится к подключению проекта-потребителя. Публикуемый пакет
проверяется для `claude` и `codex`, чтобы подтвердить переносимость, но такая
проверка не меняет пользовательский выбор цели.

## Основание

Текущие требования продукта; `ФТ-3`, `ФТ-4`; решение владельца.

## Реализация

- README даёт отдельные команды установки для Claude и Codex и требует выбрать
  одну из них.
- `ait-setup` продолжает настройку только для однозначно выбранного клиента.
- Сценарий подключения отличает клиент проекта-потребителя от целей проверки
  переносимого пакета.

## Проверка

- Валидатор сверяет обе отдельные команды с версией из `apm.yml` и отклоняет
  пользовательские команды без цели, со значением `all` или списком целей.
- Сценарий `ait-setup-result-apm-installed-client-instructions` проверяет один
  явно выбранный клиент и запрещает настройку нескольких целей по найденным
  каталогам.
- Полная проверка выполняется командой `apm run tests`.
