# ПТ-1

[К списку требований](../../requirements.md)

## Требование

Заказчик подключает продукт к целевому проекту и ведёт разработку по его ролям,
навыкам и правилам.

Подключение включает не только установку и настройку, но и первую обычную
задачу. Заказчик выбирает один клиент, устанавливает продукт в проект, выполняет
«Настрой проект», затем описывает цель, проблему или ожидаемый результат
свободными словами в том же клиенте.

Заказчик не обязан заранее знать или выбирать внутренние роли и навыки. Продукт
сам показывает понятный маршрут, подключает нужные специализации, отделяет
решения человека от самостоятельных действий и передаёт проверяемый результат на
явную приёмку.

Потребность удовлетворена, когда после настройки обычная задача проходит путь от
цели заказчика к плану, проверяемому артефакту и приёмке, а не только когда APM
создал файлы проекта.

## Реализация

- README ведёт от выбора клиента и установки через «Настрой проект» к первой
  обычной задаче и явной приёмке.
- `ait-setup` завершает настройку установленного продукта, не подменяя собой
  дальнейшую разработку.
- Роль `project-manager` принимает следующую задачу, показывает маршрут и
  подключает профильные роли и навыки.

## Проверка

1. Новый пользователь может пройти README без знания внутренних имён навыков:
   выбрать клиент, установить продукт, настроить проект и дать обычную задачу.
2. В первой задаче видны маршрут, точки решения, выполненные проверки,
   ограничения и передача результата на приёмку.
3. Отрицательный сценарий заканчивает путь после настройки либо требует от
   заказчика самому выбрать технические роли и навыки; такой путь не
   удовлетворяет ПТ-1.
4. `apm run tests` проверяет этот пользовательский путь в README и постоянном
   сценарии документации.
