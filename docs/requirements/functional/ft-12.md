# ФТ-12. Применение The Twelve-Factor App

[К списку требований](../../requirements.md)

## Требование

Продукт определяет, подходит ли The Twelve-Factor App целевому проекту, и
применяет методологию полностью или выборочно только после явного обоснования.

При прямом запросе продукт всегда выполняет оценку применимости. Без прямого
запроса он включает оценку на ранней стадии SaaS или самостоятельно
развёртываемого серверного приложения, если для проекта значимы переносимость,
облачное развёртывание, близость сред, непрерывная поставка или масштабирование.
Язык программирования, веб-фреймворк и наличие HTTP API сами по себе не
подтверждают применимость.

Для подходящего проекта на ранней стадии продукт предлагает создать ADR об
использовании всей методологии, выбранных факторов с явными отклонениями либо
другого подхода. Предложение предшествует архитектурным решениям по факторам;
продукт не создаёт и не принимает ADR без согласия владельца проекта. Отказ от
предложения фиксируется способом целевого проекта и не повторяется без прямого
запроса или существенного изменения режима поставки и эксплуатации.

Результат применения содержит статус применимости и его доказательства,
рекомендацию по ADR, полный или выборочный перечень факторов, статус каждого
выбранного фактора, доказательства, пробелы, действия, профильные маршруты и
условия пересмотра.

## Основание

Корпус знаний — `TFA-014` (область SaaS и ожидаемые эффекты),
`TFA-002`–`TFA-013` (двенадцать факторов); [ФТ-7](ft-7.md) и [ФТ-8](ft-8.md)
(дисциплина и инициативное предложение записей решений).

## Связи

- [ФТ-8](ft-8.md) включает раннее предложение ADR для подходящего проекта.
- [ФТ-9](ft-9.md) требует принять значимое решение до архитектурного действия.
- [ПР-4](../rules/pr-4.md) требует проверяемого следа корпуса знаний.

## Реализация

- [ait-twelve-factor](../../../.apm/skills/ait-twelve-factor/SKILL.md) проверяет
  применимость, предлагает ADR и ведёт полный или выборочный проход.
- [Справочник факторов][a] задаёт вопросы проверки и маршруты к профильным
  навыкам.
- `ait-routing`, `ait-architecture`, `ait-reliability` и `ait-code-construction`
  направляют подходящие задачи к профильному навыку без дублирования
  методологии.

## Проверка

1. Сценарий раннего проектирования SaaS обосновывает применимость, предлагает
   ADR до решений по факторам и оставляет принятие владельцу.
2. Сценарий библиотеки без собственного развёртывания объясняет неприменимость,
   не предлагает ADR и направляет локальные задачи к профильным навыкам.
3. Проверки срабатывания покрывают прямой запрос, неявный подходящий контекст и
   близкие задачи библиотек, локальных программ и настольных приложений.
4. `apm run tests` проверяет структуру навыка, источники, маршруты и сценарии
   результата.
