# ФТ-31. Проверка результата относительно цели

[К списку требований](../../requirements.md)

## Требование

Перед передачей результата на приёмку продукт должен проверить не только
выполнение поставленной задачи, но и соответствие результата установленной цели
и связанным с ней ожидаемым результатам или критериям.

Если задача выполнена, но результат не помогает достичь цели, продукт не должен
объявлять работу готовой. Он должен продолжить работу, предложить изменение либо
сообщить о препятствии.

Если имеющиеся свидетельства подтверждают достижение цели другим допустимым
способом, продукт не должен требовать выполнения первоначальной задачи только
ради соблюдения плана.

Если достижение цели нельзя проверить непосредственно, продукт должен
использовать заранее определённые или согласованные косвенные свидетельства,
объяснить их связь с целью и назвать ограничения проверки. Косвенные
свидетельства не должны выдаваться за непосредственное подтверждение достижения
цели.

Результат не считается готовым к приёмке, если цель потеряна, её связь с
критериями непонятна или имеющихся свидетельств недостаточно для заявленного
вывода.

## Основание

[ПТ-2. Сохранение цели при изменении задач](../user/pt-2.md) запрещает считать
выполнение задачи достаточным подтверждением готовности результата и требует
проверять результат относительно цели.

## Связи

- Реализует завершение рабочего пути
  [ПТ-2. Сохранение цели при изменении задач](../user/pt-2.md): проверяет
  результат относительно цели перед приёмкой.
- Использует цель, установленную по
  [ФТ-29. Выявление и подтверждение цели](ft-29.md) и сохранённую по
  [ФТ-30. Сохранение цели и пересмотр задач](ft-30.md).
- Уточняет [ФТ-2. Контроль качества результата](ft-2.md): выполнение задачи и
  прохождение технических проверок не заменяют проверку относительно цели.
- Поддерживает
  [ПТ-1. Путь пользователя от подключения к приёмке](../user/pt-1.md):
  пользователь получает основания для приёмки результата, а не только сообщение
  о завершении задачи.

## Реализация

- Роль [менеджера проекта](../../../.apm/agents/project-manager.agent.md)
  сопоставляет итог с целью и передаёт пользователю свидетельства и ограничения
  проверки.
- [Управление проектной задачей](../../../.apm/skills/ait-routing/SKILL.md) не
  считает выполненную задачу достаточным результатом, если цель не достигнута.
- [Обзор кода](../../../.apm/skills/ait-code-review/SKILL.md) проверяет
  реализацию относительно цели, требования, задачи и критериев готовности.

## Проверка

ФТ-31 считается выполненным, если перед приёмкой продукт связывает результат и
свидетельства с установленной целью, не принимает выполнение задачи за
достижение цели и явно ограничивает вывод при недостаточной проверяемости.

1. Если задача выполнена, но связанный с целью ожидаемый результат не получен,
   продукт не передаёт работу как готовую.
2. Если свидетельства подтверждают достижение цели допустимым способом без
   выполнения первоначальной задачи, продукт оценивает результат по цели, а не
   по соблюдению исходного плана.
3. Если критерии подтверждают только техническое действие, но не ожидаемый
   результат, проверка считается недостаточной.
4. Если цель нельзя проверить непосредственно, продукт использует заранее
   определённые или согласованные косвенные свидетельства и объясняет их связь с
   целью.
5. Если ограничения не позволяют подтвердить достижение цели, продукт сообщает
   об этом и не заявляет о подтверждённом достижении.
6. Итоговая передача показывает установленную цель, полученный результат,
   свидетельства и ограничения проверки.
7. Сценарий считается неуспешным, если цель потеряна, задача объявлена
   достаточным результатом сама по себе или косвенное свидетельство выдано за
   непосредственное подтверждение.
