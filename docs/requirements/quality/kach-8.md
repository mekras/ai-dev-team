# КАЧ-8. Завершаемость управляемой проверки

[К списку требований](../../requirements.md)

## Требование

Активная управляемая проверка должна воспроизводимо доходить до завершения либо
явного препятствия без дополнительных команд «продолжай» от пользователя.

Управляемый режим запускается только при наличии контроллера продолжения уровня
`/goal` или равнозначного механизма. Обычная инструкция навыка не считается
достаточной гарантией. Первоначальный запрос привязывает проверку к доступному
контроллеру без дополнительной технической команды пользователя. Если
подходящего контроллера нет, продукт сообщает об ограничении и предлагает ручной
возобновляемый режим без обещания автоматического завершения.

До и после каждого шага продукт сохраняет локальное состояние, связанное с
текущим рабочим каталогом и не добавляемое в Git. Состояние содержит как минимум
версию формата, снимок проверяемой области, инвентаризацию возможностей, текущую
область работы, найденные проблемы, решения пользователя, выполненные проверки и
следующее действие.

Состояние воспроизводит обязательные барьеры полной проверки. Для первого
барьера оно хранит результат поиска и полный найденный состав концепции, способ
обнаружения и доказательства смысловой проверки по
[ФТ-22](../functional/ft-22.md). Для второго барьера оно хранит полный доступный
состав корпуса знаний, технический допуск, смысловую проверку и их результаты
по [ФТ-24](../functional/ft-24.md). Допустимое следующее действие определяется
этими требованиями: до завершения барьера состояние не открывает зависимую
работу, а неуспешный результат допускает только исправление проблемы текущего
этапа и его повторную проверку.

Состояние хранит полный проверяемый след инвентаризации и каждого применения,
который требуют [ФТ-21](../functional/ft-21.md) и ФТ-22. Этот след должен
сохраняться после прерывания и позволять проверить прежний результат без
домысливания. При ожидании решения состояние хранит самодостаточный запрос по
ФТ-22, связанный с текущим снимком и дополненный границей изменения и способом
проверки.

Процесс различает состояния:

- «выполняется»
- «ожидает решения»
- «заблокировано»
- «прервано»
- «завершено»
- «завершено с принятыми рисками»

Агент не выдаёт итоговый ответ, пока процесс находится в состоянии
«выполняется». После прерывания он восстанавливает следующий шаг из локального
состояния. Изменение входящих в область файлов вне согласованного исправления
останавливает зависимую работу до уточнения, чтобы не смешивать результаты
разных состояний репозитория.

Статус «завершено» допустим, только если все обнаруженные применимые области
получили конечный результат, все найденные проблемы исправлены или признаны
неприменимыми, все исправления проверены, а непроверенные области отсутствуют.
Статус «завершено с принятыми рисками» дополнительно допускает оставшиеся
неблокирующие проблемы только при явном решении пользователя по каждой из них.

Архитектурные решения описаны в

## Проверка

1. Длительный сценарий проходит не менее трёх автоматических продолжений без
   команды пользователя и достигает конечного состояния.
2. Промежуточная сводка в состоянии «выполняется» не содержит признака
   завершения и сопровождается следующим автоматическим шагом.
3. Прерывание после сохранённого шага возобновляет работу с назначенного
   следующего действия без потери проблем и решений.
4. Отсутствие контроллера продолжения отклоняет запуск управляемого режима и не
   маскируется обычной инструкцией «работай до конца».
5. При доступном контроллере первоначальный запрос запускает управляемый режим
   без дополнительной команды пользователя.
6. Непроверенная применимая область или нерешённая блокирующая проблема не
   допускает статусы завершения.
7. Изменение проверяемого файла вне согласованной группы останавливает зависимый
   этап и показывает расхождение.
8. Самооценка `passed` без отдельного применения и наблюдаемого доказательства
   не допускает закрытие этапа или процесса.
9. Конечный переход повторно вычисляет живой снимок Git и инвентаризацию и
   отклоняется при расхождении с сохранённым состоянием.
10. Прерывание после любого применения сохраняет его обоснование приоритета,
    результат и наиболее ценное известное следующее действие.
11. Область остаётся открытой, если проверочная возможность не содержит
    предметного артефакта, охвата или проверяемых выводов, смысловая проверка не
    содержит наблюдений, связей и отклонённого опровержения либо полный класс
    документов выбран частично, не прошёл обязательный критерий или содержит
    найденную проблему. Отсутствующее доказательство нельзя заменить ручной
    записью успешного статуса.
12. Ожидание решения недоступно без сохранённого запроса по ФТ-22, связанного с
    текущей группой проблем и живым снимком Git. Изменение снимка очищает запрос
    и прерывает процесс.
13. Миграция состояния, созданного до появления барьера концепции,
    архивирует прежний снимок и открывает новый проход с поиска концепции.
    Прежние применения не доказывают соблюдение нового порядка.
14. Состояние не открывает остальные области, если первая предметная работа не
    является доказанной смысловой проверкой концепции, эта проверка неуспешна
    или после неё не завершён второй этап по ФТ-24. Ручная запись успешного
    статуса не заменяет доказательства.
