# КАЧ-2. Переносимость

[К списку требований](../README.md)

## Требование

Продукт хранит общий смысл правил, ролей, навыков и контекста в переносимом
источнике, а инструментальные файлы получает из него через APM или узкие
адаптеры. Например, общее проектное правило размещается в переносимом слое для
`AGENTS.md`, а не поддерживается независимо только в `CLAUDE.md`.

Правило для агента доходит до него в каждой поддерживаемой оснастке и в любом
режиме менеджера, в том числе когда `AGENTS.md` целевого проекта написан
вручную.

Порядок действий при неполном чтении доступен в точке входа до открытия
маршрутизатора. При усечении вывода агент дочитывает недостающие части до
зависящей работы. Если получить их нельзя, агент сообщает об ограничении и
останавливает только зависящую работу.

Инструментальное исключение допустимо, только если переносимый примитив не может
выразить нужную возможность. Исключение должно назвать:

- недостающую возможность и способ её проверки,
- затронутые и незатронутые клиенты,
- переносимый источник общего смысла или причину его отсутствия,
- границу адаптера,
- условие пересмотра или удаления исключения.

## Реализация

- Переносимые примитивы хранятся в `.apm/`, а `apm.yml` объявляет цели `claude`
  и `codex`.
- [Инструкция подключения][a] задаёт порядок дочитывания и открывает
  маршрутизатор. Для рукописного `AGENTS.md` порядок дочитывания закрепляют
  при настройке через `ai-agents-md-maintenance`.
- Полный переносимый протокол находится в
  [ait-routing](../../../.apm/skills/ait-routing/SKILL.md), а не в отдельных
  копиях клиентских инструкций. Правило, которое действует в любом режиме
  менеджера, размещается в маршрутизаторе вне шагов полного маршрута либо в
  общих правилах `.apm/context/`, которые маршрутизатор требует читать.
- `apm run tests` компилирует коллекцию с проверкой для обеих заявленных целей.
- `apm run tests` сопоставляет каждый раздел инструкции подключения с разделом
  маршрутизатора. Перенесённое из инструкции правило проверка отклоняет, если
  его опорные формулировки снова появились в ней или в другом переносимом
  источнике. Пересказ правила без этих формулировок она не обнаруживает.

## Проверка

1. Одинаковое правило находится в одном переносимом источнике, а не в двух
   независимо сопровождаемых клиентских копиях.
2. `apm compile --validate --local-only` успешно выполняется для `codex` и
   `claude`.
3. Для инструментального исключения перечислены возможность, клиенты, граница и
   условие пересмотра.
4. Проверка отклоняет исключение, обоснованное только удобством конкретного
   клиента или привычкой автора.
5. Правила, применяемые после загрузки маршрутизатора в любом режиме
   менеджера, находятся в маршрутизаторе вне шагов полного маршрута или в
   общих правилах, которые он требует читать в любом режиме.
6. Проверка отклоняет раздел инструкции подключения без соответствующего
   раздела маршрутизатора, а также опорные формулировки перенесённого правила
   в ней или в другом переносимом источнике.
7. В сгенерированных точках входа Codex и Claude Code порядок дочитывания
   предшествует указанию открыть маршрутизатор. Для рукописной точки входа
   это условие проверяется при настройке проекта.
