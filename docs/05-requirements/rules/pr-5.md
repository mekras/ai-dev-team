# ПР-5. Самоприменение продукта

[К списку требований](../README.md)

## Требование

Проект применяет собственный продукт при своей разработке: подключает его роли и
навыки и работает по ним, опираясь на те же роли, навыки и правила, что и
целевой проект. Способ подключения для разработки продукта может отличаться от
установки заказчиком.

Авторитетный переносимый источник находится в `.apm/`. Команда
`apm install --frozen` разворачивает из него рабочие навыки и роли в клиентские
каталоги текущего репозитория. Изменение сгенерированной проекции не заменяет
изменение источника.

Локальные инструкции, настройки моделей и запускатели подагентов могут дополнять
продукт для разработки репозитория, но не считаются доказательством
самоприменения и не переносятся в `.apm/` без отдельного продуктового решения.

## Основание

[Концепция](../../01-concept/README.md) задаёт системное применение практик на
всём
протяжении проекта. Публичный веб-источник о навыках агентов требует опирать
навыки на реальный опыт и проверять их на реальных задачах[^askl-001].
Самоприменение создаёт такой проверяемый контекст для собственного продукта.
[ПР-3](pr-3.md) отделяет переносимое ядро от локальных средств. Проверка
установленной проекции нужна, потому что целевые проекты исполняют развёрнутые
роли и навыки, а не исходное дерево `.apm/`.

## Реализация

- `AGENTS.md` требует менять собственные роли и навыки в `.apm/`, затем
  выполнять `apm install --frozen` и `apm audit --ci`.
- `.agents/` и `.claude/` игнорируются как рабочие проекции, роли Codex в
  `.codex/agents/` отслеживаются для запуска в этом репозитории.
- `docs/operations/development.md` объясняет разработчику границу источника,
  проекций и
  локальных настроек моделей.
- `tools/validate-apm-package-structure.py` сверяет каждый собственный
  `SKILL.md` с установленной копией и тело каждой продуктовой роли с проекцией
  Codex.

## Проверка

1. `apm run tests` отклоняет отсутствующую или устаревшую рабочую проекцию
   собственного навыка или роли.
2. `apm install --frozen` восстанавливает проекции из `.apm/` и файла
   блокировки.
3. `apm audit --ci` подтверждает отсутствие дрейфа установленного состава.

[^askl-001]:
    Публичный веб-источник о создании, описании и оценке навыков агентов, раздел
    «Start from real expertise». Внутренние идентификаторы утверждений:
    `ASKL-001`, `ASKL-002`.
