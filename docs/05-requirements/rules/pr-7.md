# ПР-7. Анализ влияния после изменения

[К списку требований](../README.md)

## Требование

После изменения любого проектного артефакта, входящего в договор влияния,
продукт выполняет сквозной анализ по [ФТ-25](../functional/ft-25.md).

До завершения задачи агент обязан:

1. назвать изменённые вершины, пути и аспекты
2. получить полное транзитивное замыкание графа
3. проверить каждую достигнутую вершину указанным для неё профильным способом
4. зафиксировать путь влияния и итог проверки
5. обновить граф при появлении нового артефакта или установленной зависимости

Форматирование или перенос без изменения смысла не освобождают от сопоставления.
Для них выбирается аспект `structure` или `documentation`, а договор определяет,
какие зависимости применимы.

## Основание

[Концепция продукта](../../01-concept/README.md) требует системного применения
проверок в
целостном контуре разработки.
[БТ-2. Раннее выявление ошибок и упущений](../business/bt-2.md) требует не
переносить последствия ошибки дальше по проекту. [ФТ-25](../functional/ft-25.md)
задаёт общий договор и критерий завершённости.

## Реализация

- `ait-routing` включает сквозной анализ после изменения в общий маршрут.
- `ait-impact-analysis` вычисляет влияние и проверяет закрытие затронутых
  вершин.
- Корневые инструкции агента указывают путь к графу и запрещают завершать задачу
  с незакрытым влиянием.

## Проверка

1. Сценарий изменения требования отклоняется, если результат проверяет только
   само требование или непосредственных потомков.
2. Сценарий несмыслового изменения выполняет сопоставление с аспектом и может
   закончиться без зависимых вершин только по фактическим рёбрам графа.
3. Несопоставленный путь блокирует завершение и требует обновить договор.
4. Итог задачи перечисляет путь и результат проверки каждой затронутой вершины.
