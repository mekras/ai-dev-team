# Требования к продукту

## Как пользоваться требованиями

Каждое требование хранится в отдельном файле и является источником истины для
своей формулировки, основания, реализации и проверки. Эта страница служит единой
точкой входа и индексом.

Требования разнесены по уровням. Каждое требование имеет устойчивый
идентификатор и краткое содержательное название. Название передаёт смысл
обязательства, а не повторяет идентификатор.

- `БТ` — бизнес-требования (зачем нужен продукт);
- `ПТ` — пользовательские требования (что нужно заказчику);
- `ФТ` — функциональные требования (что делает продукт);
- `КАЧ` — атрибуты качества;
- `ПР` — правила продукта;

У требования могут быть разделы «Основание» (откуда оно следует), «Реализация»
(где оно воплощено) и «Проверка» (как убедиться, что оно выполнено). В
бизнес-требовании раздел «Проверка» сначала прямо говорит, при каких совокупных
свидетельствах требование считается выполненным. После этого приводятся сами
свидетельства. Идентификаторы служат для трассировки и анализа влияния. В
текстах для человека используются понятные названия, а технические коды остаются
дополнительным следом (см. [КАЧ-4](quality/kach-4.md)).

Идентификаторы действующих требований уникальны. Повторное использование
идентификатора удалённого требования допускается только по явному решению
владельца продукта. История изменения должна однозначно различать прежнее и
новое требования.

## Определения

- _Продукт_ — публикуемый пакет APM `ai-dev-team`: роли, навыки, контекст и
  инструкции, которые подключаются к целевому проекту.
- _Проект_ — этот репозиторий по разработке _продукта_.
- _Целевой проект_ — сторонний проект, в котором используется _продукт_.
- _Заказчик_ — человек, управляющий разработкой _целевого проекта_.
