# ФТ-72. Выбор программы проверки проекта

[К списку требований](../README.md)

## Требование

### ФТ-72.1. Уточнение общего запроса

По общему запросу «Проверь проект» продукт помогает выбрать программу проверки
по желаемому результату, особенностям и текущему состоянию проекта. До выбора он
выполняет только краткую ориентацию, необходимую для предложения вариантов, без
запуска глубокого прохода или полной перепроверки.

### ФТ-72.2. Контекстный выбор программы

Начальный выбор включает подходящие программы от быстрой проверки явных проблем
до всесторонней проверки. Проверка перед выпуском является программой с
определённой целью. Её глубина зависит от проекта и задачи, она не является
обязательной промежуточной ступенью между быстрой и всесторонней проверками.
Продукт может включать уместные специализированные программы проекта, сохраняя
краткий понятный выбор. Пользователь может сформулировать цель своими словами.

Для каждого предложенного варианта продукт объясняет результат, охват и
относительный объём работы. Рекомендация опирается на доступный контекст. При
уже ясной цели или выбранной программе продукт не повторяет меню. Существенная
неоднозначность уточняется перед зависящим действием.

### ФТ-72.3. Выполнение выбранной программы

После выбора продукт подбирает профильные процедуры и существующие проверки
проекта. Обязательные критерии сохраняются. Быстрая проверка не подтверждает
готовность к выпуску или полный охват. Для всесторонней проверки применяется
договор ПТ-7, включая условия завершения и согласования исправлений. Углублённая
проверка начинается с широкого обзора, после которого выбираются полезные
направления без предварительного ограничения только рисками.

### ФТ-72.4. Полномочия проверки

Прямой запрос проверки не разрешает изменения, публикацию или принятие
остаточного риска за человека. Ранее выданные полномочия сохраняются.

### ФТ-72.5. Понятный результат

Итог сообщает основной вывод по выбранной задаче, существенные находки,
основания, ограничения охвата и нужный следующий шаг. Подробности доступны по
запросу. Недоступная проверка остаётся непроверенной.

## Основание

Пользователь принял общий сценарий выбора программы после команды «Проверь
проект». [UC-USR-001](../../02-use-cases/03-user/uc-usr-001.md) связывает его с
потребностью Игоря в профессиональной помощи без самостоятельного освоения всех
областей. [Концепция](../../01-concept/README.md) направляет снижение сложности
взаимодействия. Это изменение поведения по [ФТ-38](ft-38.md). Удобство такого
выбора для большинства пользователей остаётся гипотезой.

## Реализация

Общий навык `ait-project-check` выбирает программу и организует проверку через
профильные навыки. `ait-release` обращается к нему для согласованного этапа
перед выпуском. `ait-project-revalidation` сохраняет самостоятельную процедуру
полного прохода. Местные программы задаются средствами проекта без обязательного
нового формата настройки. Собственный скрипт общего навыка не требуется.

## Проверка

1. ФТ-72.1: общий запрос получает краткий контекстный выбор до предметной
   проверки.
2. ФТ-72.2: выбранная цель или программа не требует повторного меню.
3. ФТ-72.2: специализированная программа включается только при уместности для
   проекта.
4. ФТ-72.3: быстрый проход не становится полным и не подтверждает готовность
   выпуска.
5. ФТ-72.3: всесторонний проход сохраняет все обязательства и конечный барьер
   ПТ-7.
6. ФТ-72.3: углублённая проверка без выпуска не требует номера версии и не
   публикует её.
7. ФТ-72.4: запрет записи и существующие согласования сохраняются для любой
   программы.
8. ФТ-72.5: итог позволяет понять пригодность проекта для выбранной задачи,
   существенные проблемы и ограничения без чтения всего технического следа.
9. Проверка полезности охватывает общий запрос, ясную цель, специализированную
   программу и недоступную проверку. Синтетические случаи не доказывают
   удобства для большинства пользователей.
