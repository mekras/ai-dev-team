# ФТ-74. Выбор места для требований к продукту

[К списку требований](../README.md)

## Требование

Когда продукт предлагает или выбирает место записи требований к целевому
продукту, он сначала устанавливает по правилам и материалам проекта, есть ли
принятый источник требований. Если он есть, продукт использует его.

Если место ещё не определено, продукт предлагает отдельный файл требований или
раздел проектной документации. Он рекомендует наименее сложный вариант,
достаточный для объёма требований и способов работы с ними. Если пригодны
несколько вариантов с существенными различиями для проекта, продукт поясняет
эти различия и предлагает человеку выбрать до создания новой структуры.

Критерий выбора места — назначение артефакта. Инструкции для агентов задают
порядок работы агентов, а пользовательская документация помогает применять
продукт. Если в них нужно указать источник требований, достаточно ссылки.

## Основание

В разобранном случае правило ручной проверки агентом и требование к поведению
целевого продукта предлагалось закрепить в одной инструкции. Затем для
требования был предложен пользовательский обзор. В обоих случаях у команды
так и не появилось определённого места для хранения требований.

[ФТ-6. Организация структур](ФТ-006.md) задаёт единственное авторитетное
представление знания. Выбор способа хранения соразмерно процессу разработки
поддерживает книга «Разработка требований к программному обеспечению»[^sreq].

## Реализация

[Маршрутизация][route] подключает [запись требований][spec] при выборе места,
в том числе при подготовке рекомендации. Если предстоит спроектировать
структуру проектной документации, применяется [профильный навык][design].
