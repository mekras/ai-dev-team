# ФТ-64. Разбор отдельных замечаний об ошибке

[К списку требований](../README.md)

## Требование

При запросе разбора сообщения об ошибке продукт должен выделить отдельные
проверяемые замечания и для каждого сопоставить ожидаемое и фактическое
поведение. Результат должен сохранять связь с исходным сообщением, условия
проявления, основания ожидания, свидетельства фактического поведения, способ
проверки и ограничения вывода.

Исходный текст может быть передан в диалоге или получен из доступного источника
по правилам целевого проекта. Недостающие сведения продукт должен обозначить
явно. Результаты проверки одного замечания не заменяют проверку остальных.

## Основание

[Концепция продукта](../../01-concept/README.md) требует проверяемого результата
и управления необходимой сложностью. Разделение составного сообщения позволяет
работать с отдельными замечаниями, сохраняя их основания и границы проверки.

## Связи

- [ФТ-65](ft-65.md) определяет оценки поведения и полноты спецификации.

## Проверка

1. В сообщении с несколькими замечаниями каждое прослеживается до исходного
   текста и получает собственное сопоставление ожидания и наблюдения.
2. Вывод по коду обозначен как вывод по коду. Он не выдаётся за воспроизведение
   поведения в среде пользователя.
3. При недоступной проверке результат называет её границу, недостающие
   свидетельства и способ их получить.
4. Переданный в диалоге исходный текст позволяет начать разбор без трекера,
   поставляемого скрипта и определённой системы контроля версий.
