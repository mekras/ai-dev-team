# ФТ-66. Дальнейшая работа после разбора ошибки

[К списку требований](../README.md)

## Требование

По каждому замечанию из сообщения об ошибке продукт должен определить состав
дальнейшей работы, её предметную принадлежность и условия продолжения.
Результат должен связывать работу с вердиктом, состоянием спецификации,
свидетельствами и требуемой проверкой результата. Если действий не требуется,
продукт должен назвать основание этого вывода.

При принятом SDD дальнейшая работа должна следовать установленному порядку
изменения спецификации и реализации. Разбор не должен сам по себе разрешать
исправления, запись во внешнюю систему или отправку сообщений. Передача и
исполнение выполняются в пределах действующих полномочий целевого проекта.

## Основание

[Концепция продукта](../../01-concept/README.md) связывает работу агентов
с проверяемым результатом и ответственностью человека. Завершённый разбор
должен позволять продолжить работу без повторного восстановления его оснований.

## Связи

- [ФТ-64](ft-64.md) и [ФТ-65](ft-65.md) определяют результат разбора.

[Навык разбора сообщения об ошибке][skill] передаёт дальнейшую работу
профильным навыкам по существующему маршруту. [Сценарии результата][cases]
проверяют границы разбора и продолжение при неполной спецификации.

## Проверка

1. При нарушении правильной спецификации продолжение сохраняет требование
   и предусматривает регрессионную проверку исправления.
2. При ошибке и неполной спецификации в принятой области SDD состав работы
   включает уточнение спецификации и требуемое подтверждение до реализации.
3. При нехватке свидетельств названы дополнительная проверка и нужные данные,
   при продуктовом выборе — нерешённый вопрос и адресат решения.
4. Запрос только на разбор заканчивается проверенными замечаниями и составом
   работы. Исправления и внешние действия не объявляются выполненными.
