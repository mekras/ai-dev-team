# ФТ-73. Понятная запись варианта использования

[К списку требований](../README.md)

## Требование

### ФТ-73.1. Заголовки по назначению раздела

Встроенный шаблон варианта использования называет разделы так, чтобы читатель
без знания методики понимал их назначение:

- «Проверяемые условия запуска» — состояние, которое обеспечено до начала
  разрабатываемой системой или её окружением и которое разрабатываемая система
  может проверить программно,
- «Гарантии при любом исходе» — состояние, которое система обеспечивает
  и при успехе, и при неудаче,
- «Гарантии при успехе» — состояние, которое система дополнительно обеспечивает
  после успешного завершения,
- «Возможные ответвления» — ошибки и другие пути к успеху.

Одно понятие называется одинаково в шаблонах, правилах и проверках продукта.
Исходный термин книги Коберна указывается один раз для связи с источником.
Явно введённый проектный шаблон сохраняет приоритет по
[ФТ-61](ft-61.md).

### ФТ-73.2. Единообразная запись ответвлений

Во встроенном шаблоне условие ответвления записывается отдельной строкой и
завершается точкой. Обработка всегда записывается вложенными нумерованными
шагами, даже если действие одно. Последний шаг обработки содержит только
фразу итога: «Сценарий продолжается с шага N», «Сценарий завершается успехом»
или «Сценарий завершается неудачей». Номер шага возврата обязателен.

Новое условие внутри шага обработки не скрывается: оно становится отдельным
или вложенным ответвлением. Буквы ответвлений берутся из кириллицы. Явно
введённый проектный шаблон сохраняет свою запись по [ФТ-61](ft-61.md).

## Основание

Пользователь 19 ноября 2026 года подтвердил названия разделов, отдельный шаг
итога ответвления и переименование понятий во всех правилах продукта. Создание
проверочного скрипта формата отложено. Затем пользователь заменил двоеточие
в строке условия на точку: условие — законченное предложение, а шаги
обработки начинаются с прописной буквы. Дельта классифицирована как
`specification_change` и подтверждена до реализации.

Книга Алистера Коберна «Современные методы описания функциональных требований
к системам», раздел «Расширения и обработка альтернатив»: обработка
ответвления похожа на малый вариант использования с шагами и завершением
через возврат, альтернативный успех или отказ, а условие наблюдаемо.
Раздел «Предусловия, гарантии и защита интересов»: предусловие описывает
состояние, которое система уже гарантирует перед запуском. Утверждения
корпуса: `SMFR-018`, `SMFR-021`, `SMFR-022`.

Руководство Write the Docs, раздел «SEO for documentation»: заголовки
ориентируются на задачу читателя. Утверждение корпуса: `WTDG-071`.
[Концепция](../../01-concept/README.md) ставит управление сложностью главным
техническим императивом: одно имя для понятия и один образец записи снижают
нагрузку на читателя.

## Проверка

1. Обработка ответвления из одного действия записана вложенным шагом, а не
   в строке условия.
2. Каждое ответвление завершается отдельным шагом итога, возврат указывает
   номер шага.
3. Встроенный шаблон, правила и проверки используют одни и те же названия
   разделов.
4. Латинские буквы в номерах ответвлений считаются дефектом.
5. Скрытое условие «если…» в шаге обработки считается дефектом.
6. Проектный шаблон с другими названиями и записью не переписывается под
   встроенный.
