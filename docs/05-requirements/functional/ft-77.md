# ФТ-77. Диаграмма для согласования устройства кода

[К списку требований](../README.md)

## Требование

Агент следует правилам целевого проекта о показе диаграмм при согласовании
устройства кода. Если проект не определил порядок для текущего случая, агент
до реализации показывает человеку диаграмму для согласования существенного
изменения ответственности или зависимостей в коде.

Агент показывает часть структуры, от которой зависит решение. Для статической
структуры основное представление — диаграмма классов UML с понятными
подписями элементов и связей. Если решение касается порядка взаимодействий,
агент выбирает соответствующее представление, например диаграмму
последовательности. Вместе с диаграммой агент формулирует вопрос, который
предстоит решить.

При первой необходимости агент согласует с человеком доступный формат показа
и сохраняет подтверждённый выбор в `.ai-dev-team/state.yml` целевого проекта.
При следующих показах агент использует сохранённый формат, если он доступен.
Если формат недоступен, агент согласует доступный способ показа.

## Основание

Поручение владельца сделать устройство предлагаемого кода понятным до
реализации, в том числе человеку, который плохо знает язык проекта.
Приоритет правил целевого проекта и порядок по умолчанию подтверждены
в обсуждении задачи.

## Реализация

- [Диалог настройки проекта][setup] описывает хранение проектного формата.

## Проверка

1. При явном правиле целевого проекта агент применяет его к текущему решению.
2. При отсутствии такого правила человек видит диаграмму существенного
   изменения структуры до реализации. На диаграмме читаются затронутые
   обязанности и зависимости, рядом сформулирован вопрос для согласования.
3. Локальная правка без существенного структурного изменения не требует
   диаграммы по умолчанию.
4. При первом показе агент согласует формат до записи. В следующей сессии
   использует сохранённый формат, если он доступен, а при недоступности
   согласует другой способ показа.
