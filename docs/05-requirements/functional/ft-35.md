# ФТ-35. Нумерация по уровням

[К списку требований](../README.md)

## Требование

Нумерация вариантов использования должна начинаться заново внутри каждого
уровня, определённого по [ФТ-34. Уровни вариантов использования](ft-34.md).
Устойчивый идентификатор должен включать обозначение уровня либо другой
контекст, который сохраняет однозначность идентификатора во всём проекте.

При проверке существующего набора продукт должен считать ошибкой одну сквозную
числовую последовательность через разные уровни. Ошибка выявляется без
отдельного запроса пользователя о нумерации.

## Основание

Явное решение пользователя от 2 августа 2026 года: сквозная нумерация через
уровни выглядит рваной и скрывает структуру набора.

## Связи

- Использует уровни из [ФТ-34. Уровни вариантов использования](ft-34.md).
- Поддерживает [БТ-2. Раннее выявление ошибок и
  упущений](../business/bt-2.md): неподходящая схема нумерации выявляется до
  появления большого числа ссылок на карточки.

## Реализация

- [Шаблоны вариантов использования][templates] задают отдельные счётчики и
  пример однозначных идентификаторов с обозначением уровня.
- [Запись требований](../../../.apm/skills/ait-req-specification/SKILL.md)
  предлагает отдельную нумерацию до создания карточек.
- [Проверка требований](../../../.apm/skills/ait-req-validation/SKILL.md)
  классифицирует сквозную нумерацию через уровни как ошибку.

## Проверка

ФТ-35 считается выполненным, если продукт нумерует карточки отдельно внутри
уровней и выявляет сквозную нумерацию в готовом наборе.

1. Первый вариант каждого уровня получает номер `001` или эквивалентный первый
   номер выбранной схемы.
2. Идентификаторы разных уровней остаются однозначными.
3. Готовый набор со сквозными номерами между уровнями признаётся ошибочным.
