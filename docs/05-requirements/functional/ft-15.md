# ФТ-15. Переход от гипотезы к решению

[К списку требований](../README.md)

## Требование

Гипотеза может служить основанием проектного решения до завершения проверки,
если в записи решения видны её фактический статус, недостающие свидетельства,
связанные риски и причина, по которой решение нельзя отложить. Такое решение не
считается подтверждением гипотезы.

Если следующий шаг содержит значимый выбор, продукт применяет `ait-decisions` и
связывает запись решения и запись гипотезы в обе стороны. Подтверждённая
гипотеза становится свидетельством для выбора, но сама выбором не является.
Опровергнутая гипотеза требует отдельной записи решения только тогда, когда сам
отказ становится значимым проектным решением.

## Основание

[ПТ-5. Работа на основе гипотез](../user/pt-5.md) допускает решения на временном
основании, не скрывая его недостаточную обоснованность. Книга «Эволюционная
архитектура. Поддержка непрерывных изменений» рассматривает функции как
проверяемые гипотезы, а последующие решения — как результат собранных
данных.[^evar-hypothesis-driven]

## Реализация

- [ait-hypotheses](../../../.apm/skills/ait-hypotheses/SKILL.md) передаёт в
  решение фактический статус гипотезы, пробелы и риски.
- [ait-decisions](../../../.apm/skills/ait-decisions/SKILL.md) оформляет
  значимый выбор по полученному свидетельству.
- [ait-routing](../../../.apm/skills/ait-routing/SKILL.md) сохраняет границу
  между подтверждением и решением.

## Проверка

1. Решение по непроверенной гипотезе показывает её статус, недостающие
   свидетельства, риски и причину срочности.
2. Принятие решения не изменяет статус гипотезы и не считается её
   подтверждением.
3. Значимый выбор создаёт взаимно связанные записи гипотезы и решения.
4. Изменение не выполняется до решения, требуемого правилами целевого проекта.
5. Отрицательный результат не создаёт запись решения без отдельного значимого
   выбора.
