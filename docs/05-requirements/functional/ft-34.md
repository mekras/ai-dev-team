# ФТ-34. Уровни вариантов использования

[К списку требований](../README.md)

## Требование

При создании набора вариантов использования продукт должен до детализации
отдельных карточек предложить разделение по уровням целей. По умолчанию продукт
рассматривает обобщённые цели, обзорные цели, цели пользователя и подфункции,
но позволяет целевому проекту обоснованно изменить состав уровней.

При проверке существующего набора продукт должен считать ошибками отсутствие
разделения по уровням. Эта ошибка выявляется без отдельного запроса пользователя
о структуре.

## Основание

Явное решение пользователя от 2 августа 2026 года: разделение по уровням нужно
предлагать сразу, а его отсутствие в целевом проекте нужно считать ошибкой.

[Утверждения SMFR о вариантах
использования](../../../knowledge/data/smfr/items/text/statements.yml) требуют
явно удерживать уровень цели (`SMFR-003`) и начинать работу вширь с границ,
действующих лиц и целей до детализации (`SMFR-029`, `SMFR-030`). Отдельная
нумерация по уровням закреплена решением пользователя, а не выведена из SMFR.

## Связи

- Развивает [ФТ-11. Выявление требований](ft-11.md): структура набора
  появляется до детализации сценариев.
- Задаёт уровни для [ФТ-35. Нумерация по уровням](ft-35.md).
- Поддерживает [БТ-2. Раннее выявление ошибок и
  упущений](../business/bt-2.md): смешение уровней обнаруживается до записи
  подробных карточек.

## Реализация

- [Шаблоны вариантов использования][templates]
  задают начальное разделение и пример схемы идентификаторов.
- [Запись требований](../../../.apm/skills/ait-req-specification/SKILL.md)
  предлагает структуру до выбора шаблона карточки.
- [Проверка требований](../../../.apm/skills/ait-req-validation/SKILL.md)
  классифицирует смешение уровней как ошибку.
- [Проектирование
  взаимодействия](../../../.apm/skills/ait-ux-design/SKILL.md) предлагает уровни
  до детализации сценариев.

## Проверка

ФТ-34 считается выполненным, если продукт предлагает уровни до детализации и
выявляет отсутствие разделения в готовом наборе.

1. При запросе нового набора продукт сначала показывает предлагаемую структуру
   уровней, не ожидая дополнительного вопроса.
2. Готовый набор без уровней признаётся ошибочным.
