# ПТ-5. Работа на основе гипотез

[К списку требований](../README.md)

## Требование

Продукт должен позволять пользователю выдвинуть и зафиксировать проверяемую
гипотезу, когда доступных сведений недостаточно для обоснованного требования, и
по явному решению пользователя временно использовать её как основание
ограниченной разработки и связанных проектных решений.

Продукт должен сохранять видимой недостаточную обоснованность гипотезы и не
представлять её как требование или установленный факт. Работа по гипотезе должна
быть направлена на получение свидетельств, по которым пользователь сможет
сформулировать требование, опровергнуть гипотезу или признать, что данных для
вывода пока недостаточно.

Запись гипотезы должна сохранять ход работы, полученные свидетельства, вывод и
связи с принятыми на её основании решениями, задачами и требованиями.

## Основание

Требование выявлено при применении продукта в целевых проектах. В работе
возникают предположения, достаточно ценные для проверки и проектных решений, но
ещё недостаточно обоснованные для требований. Если продукт признаёт основанием
разработки только готовые требования, проект либо останавливается, либо скрывает
неопределённость за преждевременным требованием.

Разработка на основе гипотез и данных позволяет выпускать изменения как
проверяемые гипотезы, а дальнейшие решения принимать по собранным
свидетельствам.[^evar-hypothesis-driven]

## Проверка

ПТ-5 считается выполненным, если при недостатке сведений для обоснованного
требования пользователь может явно принять проверяемую гипотезу как временное
основание ограниченной работы, а продукт сохраняет неопределённость видимой,
собирает свидетельства и ведёт к обоснованному следующему состоянию.

1. Недостаточно обоснованное предположение регистрируется как гипотеза, а не как
   требование или установленный факт.
2. До начала работы пользователь явно решает, можно ли использовать гипотезу как
   временное основание, и видит границы и риски такой работы.
3. Задачи и решения в разрешённых границах ссылаются на гипотезу и сохраняют её
   фактический статус.
4. Полученные в ходе работы свидетельства добавляются в запись гипотезы.
5. Достаточное основание направляется в обычный процесс формирования и
   согласования требования. Подтверждение гипотезы само по себе не создаёт
   требование и не означает принятого решения.
6. Опровержение и недостаток данных сохраняются как самостоятельные результаты.
7. `apm run tests` проверяет работу по гипотезе, границу с требованием и
   переходы к следующим проектным шагам.
