# Файловая структура корпуса

Корпус знаний хранит источники, единицы источников, первичные материалы,
нормализованные артефакты и утверждения так, чтобы от проектного вывода можно
было вернуться к конкретному материалу источника.

Этот документ — обзор для читателя. Нормативный источник раскладки — договор
[`corpus-layout-contract.md`](../../.apm/skills/kc-inventory/references/corpus-layout-contract.md).
Точные обязательные поля источников, единиц и утверждений, стадии обработки,
виды утверждений и перечень проверок заданы там и в переносимом валидаторе
`.apm/skills/kc-inventory/scripts/validate-corpus-layout.py`. Обзор их не
повторяет, чтобы у каждого факта раскладки был один авторитетный дом.

Проект может выбрать собственные имена каталогов; ниже — переносимая раскладка,
которую навыки корпуса дают как стартовый договор.

## Общая схема

```text
corpus.yml
catalog.yml
index/
  items.yml
data/
  <source>/
    source.yml
    items.yml
    выгрузка.local.zip   # неотслеживаемое сырьё уровня источника (маркер *.local.*)
    <units>/
      <unit>/
        item.yml
        <artifact>
        исходник.local.pdf  # неотслеживаемое сырьё этой единицы
        statements.yml
```

## Корень корпуса

| Путь | Назначение |
| --- | --- |
| `corpus.yml` | Договор корпуса: версия, корни данных, шаблоны путей, политика доступа, поддерживаемые стадии и проверки. |
| `catalog.yml` | Навигационный список источников: идентификатор, название и путь к каталогу источника. |
| `index/items.yml` | Производный навигационный индекс единиц. Выводится из `data/*/items.yml` и синхронен с ним; его можно перегенерировать. |
| `data/` | Отслеживаемый слой источников и их переносимых артефактов. |

Полные данные и неотслеживаемые материалы принадлежат источнику и лежат в его
каталоге. Отдельного корневого слоя для неотслеживаемых файлов нет.

Подробнее о выборе способа хранения см.
[«Как выбирать способ работы с источником»](../20-sources/03-source-decisions.md).

## Каталог источника

```text
data/<source>/
  source.yml
  items.yml
```

`data/<source>/source.yml` описывает источник: название, статус, приоритет,
технический носитель, смысловой вид, доступ, стратегию хранения, способ
получения, политику копирования и ограничения. Точный список обязательных полей
задан договором раскладки и валидатором, а не этим обзором.

Если источник подключает внешний корпус знаний по этим же правилам, в
`source.yml` добавляется блок `external_corpus`. Он фиксирует договор внешнего
корпуса, режим `peer` и при необходимости локальный checkout в каталоге под
маской `*.local`, например `data/<source>/external-corpus.local/`.

`<source>` в пути — файловый slug источника. Обычно его записывают в нижнем
регистре, чтобы путь был переносимым и удобным для командной строки. Стабильный
идентификатор источника хранится отдельно в поле `id` и может оставаться
коротким кодом в верхнем регистре, например `SAHP` при пути `data/sahp/`.

`data/<source>/items.yml` хранит индекс единиц источника: страниц, файлов,
сообщений, записей, глав, выпусков или других фрагментов, с которыми корпус
работает отдельно.

Для источника `source_kind: knowledge_corpus` в режиме
`external_corpus.use_as: peer` локальный `items.yml` можно не создавать:
агент берёт индексы единиц, утверждения и отчёты прямо из подключённого
внешнего корпуса.

## Единица источника

```text
data/<source>/<units>/<unit>/
  item.yml
  normalized.md
  statements.yml
```

`item.yml` описывает конкретную единицу источника: локатор, статус доступа,
стадию обработки, ограничения и ссылки на артефакты рядом с этой единицей.

Артефакты единицы зависят от носителя и способа обработки:

| Артефакт | Когда появляется |
| --- | --- |
| исходный файл или снимок | материал можно хранить в корпусе; |
| расшифровка | источник содержит аудио, видео или речь; |
| результат OCR | источник содержит скан или изображение текста; |
| `normalized.md` или другой нормализованный файл | материал приведён к виду для чтения, поиска и извлечения утверждений; |
| `statements.yml` | из материала извлечены проверяемые утверждения. |

`statements.yml` хранится рядом с материалом, из которого извлечены
утверждения. Так проще проверить связь: источник → единица источника →
артефакт → утверждение.

У утверждения может быть необязательное поле `kind` (вид утверждения). Оно не
заменяет `status`: `kind` говорит, что это за утверждение, а `status` —
насколько оно проверено. Определения видов и остальные поля утверждения заданы
в договоре раскладки; старые утверждения без `kind` остаются допустимыми.

Для полной проверки готовности корпуса используйте строгую проверку утверждений:

```bash
python3 .apm/skills/kc-inventory/scripts/validate-corpus-layout.py knowledge --strict-statements
```

Что именно ловит строгий режим, см. в договоре раскладки.

## Индексы и ссылки

Индексы дают навигацию по корпусу и являются производным слоем. Материалы
источников хранятся в карточках, артефактах и локальном слое источника.

`catalog.yml` индексирует источники. `data/<source>/items.yml` индексирует
единицы одного источника. `index/items.yml` может сводить единицы всех
источников в один список и должен оставаться синхронным с `data/*/items.yml`;
его не ведут как самостоятельный источник данных.

Пути к переносимым артефактам записываются относительно корня репозитория.
Абсолютные локальные пути, токены, сессии, пароли и закрытые ссылки не попадают
в отслеживаемые файлы.

У внешнего корпуса знаний локальная карточка источника может не иметь своего
индекса единиц: в этом случае путём навигации служит сам подключённый корпус.

## Локальный слой источника

Материалы, которые нужны в работе, но остаются вне Git — полные книги без права
публикации, тяжёлые медиа, временные загрузки, рабочие файлы извлечения,
приватные снимки и закрытые данные — лежат рядом со своим владельцем, файлом с
маркером в имени. Маркер отделяет неотслеживаемый файл от отслеживаемых и
исключает его из Git.

- Материал одной единицы (запись встречи, исходный файл документа, вложение
  страницы) кладите в папку этой единицы: постоянное сырьё — `*.local.*`
  (например `запись.local.mp4` рядом со `стенограмма.md`), временный рабочий
  файл — `*.tmp.*`. Перечисляйте такие файлы в `files.local` карточки единицы
  `item.yml`.
- Материал уровня источника или файл, который человек кладёт вручную до того,
  как заведена единица, кладите прямо в папку источника `data/<source>/` тем же
  маркером.
- Каталог, который нельзя свести к файлу (клон внешнего корпуса), именуйте с
  суффиксом `.local` (`external-corpus.local/`).

Так весь материал по одной единице собран в её папке, а маски `.gitignore`
(`*.local.*`, `*.local`, `*.tmp.*`) держат его вне Git.

В отслеживаемом слое остаются переносимые сведения: карточка источника, хэш или
другой проверочный признак, размер и формат, ограничения доступа и публикации,
статус извлечения и разрешённые производные артефакты.

## Проверки структуры

Проверку раскладки выполняет переносимый валидатор
`.apm/skills/kc-inventory/scripts/validate-corpus-layout.py`; он же остаётся
исполняемым источником истины для обязательных полей и стадий. Перечень
конкретных проверок приведён в договоре раскладки.
