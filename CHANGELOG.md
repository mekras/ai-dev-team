# Журнал изменений

Все заметные изменения проекта документируются в этом файле.

## 0.6.4

- Уточнён маршрут `kc-setup` после диагностики структуры: при запросе на
  настройку или исправление корпуса навык должен продолжать работу через
  `kc-inventory`, а не завершать ответ только сообщением о следующей задаче.
- Уточнён `kc-inventory`: если проект без собственного договора нужно
  подготовить к проверке, переносимый договор используется как стартовый
  вариант, а текущая раскладка папок остаётся материалом для миграции, а не
  договором.

## 0.6.3

- Пересмотрен маршрут настройки и проверки корпуса: `kc-setup` больше не
  создаёт или чинит структуру корпуса, `kc-validation` не синтезирует договор
  из наблюдаемых папок, а `kc-inventory` может создавать `corpus.yml`,
  `catalog.yml` или другой договор только после отдельного решения о структуре.

## 0.6.2

- Уточнены `kc-setup` и `kc-validation`: README внутри папки корпуса больше не
  считается договором структуры и не должен создаваться как обязательный файл
  корпуса; для договора структуры нужны `corpus.yml`, `catalog.yml`, явно
  названный проектный манифест или правила структуры.

## 0.6.1

- Уточнён `kc-setup`: шаблон `AGENTS.md` больше не переносит термин «целевой
  проект» в настраиваемый проект, а новый корпус после выбора папки должен
  получать стартовую структуру по договору `kc-inventory`.
- Уточнён `kc-validation`: если проект уже заявляет корпус знаний, отсутствие
  договора структуры теперь считается формальной ошибкой, а не только
  ограничением проверки.
- Добавлен справочник навыков и сокращён README: подробности о корпусе перенесены
  в документацию, а README оставлен как входная страница с установкой, первыми
  действиями и ссылками.

## 0.6.0

- Добавлены рабочие YAML-классификаторы технических типов носителя источника и
  смысловых видов источника; шаблон карточки, инструкции навыков и переносимый
  валидатор корпуса переведены на поля `carrier_type` и `source_kind`.
- Обновлено состояние настройки проекта под `ai-dev-team` 0.10.0 и закреплено
  правило сопровождать этот журнал через `ait-changelog`.
- Добавлена пользовательская документация по корпусу знаний: обзор, типы и виды
  источников, правила выбора стратегии хранения, структура файлов корпуса и
  сценарий добавления локального файла вне Git.
- Добавлен профиль локального книжного источника для PDF, DjVu, EPUB, сканов и
  извлечённого текста: добавление источника, учёт, нормализация, конвейер,
  извлечение утверждений, проверка и аудит влияния теперь используют общий
  контракт для книг с режимом `local_only`.
- Добавлено покрытие проверок срабатывания и сценариев результата для локальных
  книг вне Git с отслеживаемыми метаданными, индексами, нормализованными
  фрагментами и производными утверждениями.

## 0.5.0

- Добавлен режим получения `external_reference` для источников, которые нельзя
  или не нужно копировать в корпус: прямой доступ к первичному источнику по
  запросу, с локатором, политикой копирования и проверкой доступа вместо
  локальной копии.
- Описаны политики копирования и режимы получения в навыках и справках по
  учёту, добавлению источников и конвейеру.
- Добавлено покрытие проверок срабатывания и сценариев результата для прямого
  доступа к источникам.
- Уточнены инструкции для агента: изменения ограничены папкой проекта и
  правилами Git.

## 0.4.0

- Добавлена обработка источников в режимах `index_only` и `on_demand` в навыках
  учёта, добавления источников и конвейера.
- Описаны стратегии хранения для крупных, дорогих и лицензионно ограниченных
  источников.
- Добавлено покрытие проверок срабатывания и сценариев результата для нового
  режима обработки источников.
