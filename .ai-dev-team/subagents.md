# Выбор маршрута работы с подагентами

Эта процедура действует в проекте ai-dev-team. Перед выбором маршрута
прочитай её целиком и получи из `.ai-dev-team/local/subagents.local.toml`
только поля `direct_execution`, `direct_execution_scope`, `subtask_routing`,
`parent_comparison`, `unknown_parent_parameters`, `parent_change`,
`assignment_basis`, `unavailable_route` и `routes` таблицы `[policy_runtime]`.
Полнота входного чтения относится к этому файлу и перечисленным полям.
Локальная настройка задаёт условия проекта и хранится вне Git. Если её нет,
маршрутизация подагентов не настроена. При ошибке чтения условий сообщи
об ограничении и считай передачу недоступной.

Получи поля выборочным чтением или выведи их через TOML-парсер.
Пример для Python 3.11+:

```sh
python3 - <<'PYTHON'
from pathlib import Path
from pprint import pprint
import tomllib

path = Path(".ai-dev-team/local/subagents.local.toml")
try:
    with path.open("rb") as stream:
        policy = tomllib.load(stream)["policy_runtime"]
except FileNotFoundError:
    print("Маршрутизация подагентов не настроена")
else:
    fields = (
        "direct_execution", "direct_execution_scope", "subtask_routing",
        "parent_comparison", "unknown_parent_parameters", "parent_change",
        "assignment_basis", "unavailable_route", "routes",
    )
    pprint({field: policy[field] for field in fields}, sort_dicts=False)
PYTHON
```

## Решение о маршруте

Определи результат, полномочия и границы родительской задачи. Проверь каждую
кандидатную ограниченную подзадачу по `[policy_runtime.routes]`. Назови
кандидатов либо укажи, что их нет. Микрозадачи выполняй напрямую, без
искусственного деления. Для остальных задач сопоставь пользу отдельного
контекста, независимости и полномочий со стоимостью постановки, передачи
входов и приёмки. При неоправданной передаче выполняй работу напрямую.

Сначала определи предметную роль по `ait-routing`. Если для неё и подзадачи
подходит маршрут с полем `role`, выбери его перед общим маршрутом класса.
Класс задаёт границы поручения, роль — профильную работу и исполнителя.
Для независимой проверки готовой правки по заданным критериям выбирай
проектную роль тестировщика. Маршрут только с `execution_class` подходит,
когда предметная роль не нужна.

`direct_execution_scope = "whole_parent_task"` относится к родительской задаче
целиком. `subtask_routing = "match_each_bounded_subtask"` требует отдельно
оценить подходящую ограниченную подзадачу, включая сбор сведений без записи
для родительской задачи с правом записи. Защищённые источники, утверждение
решений и итоговая приёмка остаются у родителя. Запись подагента допустима
только в явно разрешённых пределах контракта выбранного класса.

Если нашлась подходящая подзадача, до решения о её передаче открой
[процедуру запуска и приёмки](subagents-execution.md) и проверь контракт,
доступность маршрута и назначение для выбранной роли либо класса и оснастки.
Если процедура или назначение недоступны, применяй `unavailable_route`.
Сопоставляй модель и усилие с фактическими параметрами родительской сессии.
Исторические сведения из `policy_design` и сохранённые назначения не
подтверждают параметры этой сессии. Если параметр неизвестен, передача
допустима при самостоятельном предметном основании. Сохрани неизвестность
и укажи, что сравнение не повлияло на выбор. Если выбор зависит от недостающего
свидетельства, оставь маршрут неразрешённым до его получения или эскалации
по политике. При смене модели или усилия пересмотри сравнение. При
недоступности маршрута применяй `unavailable_route`, если поле доступно.
Сохрани требование отдельного исполнителя, если оно действует для задачи.

После входной подготовки по `AGENTS.md`, до предметной работы, зафиксируй
краткое решение. Предпочитай журнал хода текущей сессии. При делегировании
внеси решение в постановку задачи запускателя. Если оснастка не даёт способа
сохранить решение, сообщи его одной-двумя понятными фразами в промежуточном
сообщении или в плане полного режима. Не выводи отдельный служебный блок
и не повторяй эту запись в итоговом ответе.

В записи укажи объём, исход («прямое выполнение», «делегирование» или «маршрут
не разрешён»), предметное основание и существенную неопределённость.
При прямом выполнении свяжи причину с конкретным входом, полномочиями,
независимостью, приёмкой и стоимостью передачи. Если подходящая подзадача
выявится позднее, примени эту процедуру до работы над ней.
Обычное применение политики не требует запуска её настройки или аудита.
