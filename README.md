# Команда агентов для разработки ПО

`ai-dev-team` — подключаемая команда агентов ИИ для разработки ПО. Она
объединяет предметные роли, навыки, правила работы и проверки качества, чтобы
провести задачу от замысла до проверенного результата. Вы задаёте цель,
согласовываете значимые решения и принимаете работу.

В продукт входят 13 специализированных ролей. Для каждой задачи он подбирает
нужных специалистов. Аналитик уточняет основания и требования, архитектор
проектирует устройство системы, программист реализует изменения. Безопасность,
надёжность, право, пользовательский опыт и документацию проверяют профильные
специалисты. Отдельные роли готовят проверяемые сведения из корпуса знаний.

## Что поддерживает продукт

### 1. Управляемая работа с ИИ

- границы самостоятельной работы ИИ и решений человека
- подбор специалистов и этапов под задачу
- проверка результата перед утверждением человеком
- воспроизводимая установка ролей, навыков и правил через APM

### 2. Разработка на проверяемых основаниях

- корпус знаний с учётом происхождения и ограничений источников
- конвейер от первичных данных через нормализацию и извлечение утверждений к
  анализу и изменениям проекта
- согласование понятий между источниками и продуктом
- анализ влияния изменений источников на требования, решения и документацию

### 3. Требования, гипотезы и решения

- выявление, анализ, спецификация, проверка и сопровождение требований
- пользовательские сценарии, варианты использования и критерии приёмки
- проверяемые гипотезы с сохранением отрицательных результатов
- ADR, ODR и DDR для фиксации значимых решений до реализации

### 4. Архитектура и жизненный цикл системы

- архитектурные силы, компромиссы, границы компонентов и интеграции
- предметное моделирование, Clean Architecture и эволюционная архитектура
- проектирование API и распределённых систем
- C4 и ADR как представления архитектуры
- The Twelve-Factor App для подходящих сервисных приложений
- реконструируемость проекта из канонических входов и контура исполнения

### 5. Инженерная работа и организация разработки

- конструирование и рефакторинг кода, тестирование разработчиком и обзор кода
- Scrum: роли, события, артефакты, планирование, оценка и масштабирование
- сопровождение журналов изменений
- Conventional Commits, Gitmoji или рекомендации Pro Git для сообщений коммитов

### 6. Качество, безопасность и правовые ограничения

- надёжность: SLI, SLO, бюджеты ошибок, анализ отказов и устойчивость
- моделирование угроз, STRIDE, деревья атак и проверка мер защиты
- управление доступом к API, безопасность использования и разработки ИИ
- аудит безопасности и выбор средств защиты по модели угроз
- лицензирование и совместимость лицензий
- обработка персональных данных в проектах, работающих в Российской Федерации

### 7. Пользовательский опыт и документация

- персонажи, цели, сценарии, проектирование взаимодействия и проверка UX
- доступность интерфейсов и платформенные правила
- проектирование и проверка пользовательских интерфейсов
- концепция проекта, структура документации, README и техническое письмо

## Подключение к проекту

Для подключения необходим
[Agent Package Manager](https://github.com/microsoft/apm).

Выберите клиент и выполните команду в корне целевого проекта.

Для Claude:

```shell
apm install mekras/ai-dev-team#^0.21.3 --target claude
```

Для Codex:

```shell
apm install mekras/ai-dev-team#^0.21.3 --target codex
```

После установки откройте выбранный инструмент для общения с агентами в корне
проекта и дайте команду:

```text
Настрой проект.
```

Во время настройки ответьте на вопросы о проекте. Если в проекте уже есть
инструкции для агентов, просмотрите предложенные изменения и подтвердите их
замену.

## Работа с проектом

После настройки продолжайте работу в том же выбранном клиенте из корня проекта.
Опишите цель, проблему или ожидаемый результат обычными словами, например:

```text
Нужно сократить время обработки заявки. Изучи текущую реализацию, предложи
решение и после согласования внеси изменения.
```

Продукт сам подберёт специалистов и покажет план. Перед изменениями, для которых
нужен ваш выбор, он запросит подтверждение. После выполнения задачи вы увидите
результат, проведённые проверки и оставшиеся ограничения. Подтвердите работу или
верните её на доработку с замечаниями.

## Обновление продукта

Когда выходит новая версия продукта, сначала обновите зависимость для того же
клиента, который выбрали при подключении.

Для Claude:

```shell
apm update mekras/ai-dev-team --target claude
```

Для Codex:

```shell
apm update mekras/ai-dev-team --target codex
```

Затем в корне проекта дайте агенту команду:

```text
Обнови проект под новую версию ai-dev-team.
```

Агент покажет действия, которые новая версия требует от вашего проекта, и
запросит подтверждение перед каждым изменением. Если проект менять не требуется,
он сообщит об этом и завершит обновление.

Что изменилось между версиями, описано в [журнале изменений](CHANGELOG.md).
