# Проверка двенадцати факторов

Используй эту справку после положительной оценки применимости. Она задаёт
вопросы и маршруты, но не заменяет решения проекта и первоисточник.

| Фактор                                | Вопрос и свидетельства                                                                             | Основной маршрут                            |
| ------------------------------------- | -------------------------------------------------------------------------------------------------- | ------------------------------------------- |
| Кодовая база (`TFA-002`)              | Где проходит граница приложения, какая кодовая база создаёт его развёртывания?                     | `ait-architecture`                          |
| Зависимости (`TFA-003`)               | Все зависимости объявлены и изолированы, запуск не полагается на случайные пакеты среды?           | `ait-code-construction`, `ait-code-review`  |
| Конфигурация (`TFA-004`)              | Изменяемые между развёртываниями значения отделены от кода и секретов репозитория?                 | `ait-architecture`, `ait-code-construction` |
| Сторонние службы (`TFA-005`)          | Внешние службы подключаются как заменяемые ресурсы без изменения прикладного кода?                 | `ait-architecture`                          |
| Сборка, релиз, выполнение (`TFA-006`) | Стадии разделены, а выпущенный релиз воспроизводим и неизменяем?                                   | `ait-architecture`, `ait-code-testing`      |
| Процессы (`TFA-007`)                  | Сохраняемое состояние вынесено из процессов в предназначенные для него службы?                     | `ait-architecture`, `ait-reliability`       |
| Привязка портов (`TFA-008`)           | Сервис имеет явный сетевой контракт и не зависит от скрытого внедрения среды?                      | `ait-architecture`                          |
| Параллелизм (`TFA-009`)               | Виды нагрузки разделены, а масштабирование не требует изменения прикладной логики?                 | `ait-architecture`, `ait-reliability`       |
| Утилизируемость (`TFA-010`)           | Процессы быстро запускаются, штатно завершаются и выдерживают внезапную остановку?                 | `ait-reliability`, `ait-code-testing`       |
| Паритет сред (`TFA-011`)              | Различия сред известны, обоснованы и не мешают воспроизводить поведение до рабочего развёртывания? | `ait-architecture`, `ait-code-testing`      |
| Журналирование (`TFA-012`)            | Приложение отдаёт поток событий, а маршрутизацией и хранением управляет среда?                     | `ait-reliability`, `ait-code-review`        |
| Задачи администрирования (`TFA-013`)  | Разовые задачи используют тот же релиз, код, настройки и зависимости, что и основные процессы?     | `ait-architecture`, `ait-code-testing`      |

## Полный проход

Для нового приложения или общего аудита пройди все строки и по каждой укажи:

1. статус;
2. проверяемое свидетельство или его отсутствие;
3. риск либо ожидаемую пользу;
4. решение, действие или причину неприменимости;
5. владельца решения и способ проверки.

## Выборочный проход

Для ограниченной задачи сначала назови затронутые факторы и связь с задачей.
Соседний фактор добавляй только при наблюдаемой зависимости. Например, изменение
хранения настроек не требует автоматически проверять масштабирование, если
архитектура процессов не меняется.
