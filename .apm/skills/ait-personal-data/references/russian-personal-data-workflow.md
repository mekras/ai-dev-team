# Проверка обработки персональных данных в Российской Федерации

## Матрица обработки

Для каждой отдельной цели заполни:

| Поле               | Что установить                                                  |
| ------------------ | --------------------------------------------------------------- |
| Цель и процесс     | Зачем данные нужны и в каком процессе используются.             |
| Участники          | Оператор, субъект, обработчик, получатель и ответственный.      |
| Данные             | Категории, источник, специальные или биометрические признаки.   |
| Операции и системы | Сбор, хранение, передача, удаление, система и страны.           |
| Основание          | Конкретное условие обработки и доказательство его применимости. |
| Документы          | Политика, согласие, поручение, уведомление или локальный акт.   |
| Защита             | Правовая обязанность и передача технической части роли ИБ.      |
| Срок и завершение  | Срок хранения, событие удаления и подтверждение уничтожения.    |
| Статус             | Установленный факт, пробел, трактовка или решение владельца.    |

## Обязательные развилки

- При поручении обработки проверь договорный объём: цели, данные, операции,
  конфиденциальность и меры безопасности. Основание: `RUPD-003`.
- При сборе через Интернет данных граждан России отдельно проверь применимость
  требования о базах данных на территории России. Основание: `RUPD-004`.
- При иностранном получателе сначала установи, есть ли трансграничная передача,
  затем проверь уведомление, страну, исключения и ограничения. Основание:
  `RKN-003`.
- При инциденте зафиксируй время обнаружения, владельца связи с регулятором и
  передачу расследования роли ИБ. Проверяй применимость сроков 24 и 72 часа по
  актуальному источнику. Основание: `RKN-002`.
- Для технической защиты зафиксируй обязанность и передай анализ угроз, выбор и
  проверку мер роли ИБ. Основания: `RUPD-006`, `FSTC-001`.

## Эскалация

Передай решение человеку или внешнему юристу, когда:

- нет достаточных фактов о цели, субъектах, стране, получателе или основании;
- применим отраслевой режим, специальная или биометрическая категория данных;
- есть несколько правдоподобных трактовок с разными последствиями;
- нужно принять риск, утвердить документ или квалифицировать нарушение.

## Безопасная работа с материалами

Не копируй реальные персональные данные в публичные документы, Git, корпус,
проверки навыков и запросы без необходимости. Предпочитай минимальные,
синтетические или обезличенные сведения. Если для анализа нужен закрытый слой,
следуй `ait-private-knowledge`; он не заменяет защищённое хранилище секретов.
