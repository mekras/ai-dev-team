# Сквозной анализ влияния

Используй единый граф проекта, чтобы после изменения найти все потенциально
затронутые части на полной глубине зависимостей, выбрать обязательные
детерминированные проверки и направить профильную проверку.

## Когда применять

Применяй навык:

- после изменения отслеживаемого артефакта проекта
- при создании или сопровождении графа влияния проекта
- при поиске всех последствий изменения концепции, источника, требования,
  решения, реализации или другого проектного основания
- при выборе повторных проверок после исправления

Для изменения первичного источника в корпусе сначала используй профильный
`kc-impact-audit`, а этот навык продолжает анализ за границами корпуса. Полная
проверка репозитория использует этот навык как общий механизм влияния, но не
владеет графом.

## Обязательный порядок

1. Найди путь к графу в корневых инструкциях агента или в поле
   `setup.impact_graph.path` файла `.ai-dev-team-state.yml`. Если граф не
   настроен, останови изменение и направь проект в `ait-setup`.
2. Прочитай [договор графа](references/impact-graph-contract.md) и выполни:

   ```shell
   python3 \
     .agents/skills/ait-impact-analysis/scripts/impact_graph.py \
     validate --graph project-impact.json
   ```

3. Установи изменённые пути или вершины и аспект изменения. Не считай любое
   изменение смысловым автоматически. Выбери один из аспектов договора и обоснуй
   выбор по фактическому различию.
4. Если целевой проект настроил выборочные проверки, до передачи результатов
   модели запусти `selective_verification.py`. Перед настройкой и вызовом
   прочитай [договор выборочных проверок][selective-verification]. Сценарий сам
   определяет изменения относительно указанной базы Git, получает влияние,
   запускает обязательные проверки либо берёт успешный результат из кеша.

   ```shell
   python3 \
     .agents/skills/ait-impact-analysis/scripts/selective_verification.py \
     run --repo . --config project-verification.json --base origin/main
   ```

   Передай модели только отчёт сценария, указанные в нём области и ограниченный
   вывод ошибок. При полном охвате не сокращай набор проверок. Ненулевой код
   завершения означает, что ошибки проверки нужно передать на разбор, а не
   объявить результат готовым.
5. Получи полное транзитивное влияние:

   ```shell
   python3 \
     .agents/skills/ait-impact-analysis/scripts/impact_graph.py \
     trace --graph project-impact.json \
     --changed-path docs/concept.md \
     --facet semantic
   ```

6. Для каждой затронутой вершины открой перечисленные в ней профильные проверки
   и проверь показанный путь влияния. Потенциальное влияние не разрешает
   механически менять производный артефакт.
7. Присвой каждой затронутой вершине один итог:
   - `updated` — зависимый материал обновлён и проверен
   - `verified_no_impact` — путь проверен, изменение не требует правки
   - `owner_decision` — нужен содержательный выбор владельца
   - `blocked` — проверку нельзя завершить по названной причине

8. Проверь завершённость тем же набором входов:

   ```shell
   python3 \
     .agents/skills/ait-impact-analysis/scripts/impact_graph.py \
     assess --graph project-impact.json \
     --changed-path docs/concept.md \
     --facet semantic \
     --status requirements=updated \
     --status implementation=verified_no_impact
   ```

   Отсутствующий итог, `owner_decision` или `blocked` не допускает завершить
   задачу. Если правка зависимой вершины создаёт новый аспект изменения, добавь
   эту пару «вершина, аспект» в тот же набор входов и повтори трассу. Заверши
   анализ, когда новые пары больше не появляются. Не заменяй этот процесс
   отдельной ручной цепочкой локальных проверок.

9. Если новый или изменённый путь не сопоставлен вершине, либо найденная
   зависимость отсутствует в графе, обнови граф через этот навык и повтори
   анализ. Новое направление зависимости, способное изменить будущие решения,
   сначала проведи через требования и `ait-decisions`.

## Сопровождение графа

При добавлении, удалении или переносе проектного артефакта проверь сопоставление
путей. При изменении смысловой зависимости обнови ребро, его аспекты и
обоснование. Затем выполни структурную проверку и проверку покрытия:

```shell
python3 \
  .agents/skills/ait-impact-analysis/scripts/impact_graph.py \
  coverage --graph project-impact.json --repo .
```

Граф хранит только маршруты влияния и указатели на профильные проверки. Не
дублируй в нём содержание концепции, корпуса, требований, решений или
архитектуры.

## Настройка выборочных проверок

Настраивай сценарий после создания графа влияния. Скопируй
[шаблон объявления][selective-template] в целевой проект и замени примерные
области, команды и входы фактическими сведениями проекта.

1. Для каждой области перечисли вершины графа, которые её обозначают, и полный
   набор обязательных проверок. Одна проверка может относиться к нескольким
   областям.
2. Для каждой проверки задай команду без оболочки, рабочий каталог, исходники,
   тесты, настройки и зависимости, от которых зависит её результат, а также
   явный набор переменных среды и команду получения версии средства.
3. В `global_inputs` и `full_coverage_paths` перечисли граф, объявление
   проверок, манифесты и lock-файлы зависимостей, настройки сборки, генераторы,
   схемы и другие изменения, после которых выборочный охват нельзя считать
   достаточным.
4. Проверь объявление до первого запуска:

   ```shell
   python3 \
     .agents/skills/ait-impact-analysis/scripts/selective_verification.py \
     validate --repo . --config project-verification.json
   ```

Кеш хранится в каталоге Git целевого проекта и содержит только успешные
результаты. Его нельзя добавлять в репозиторий. Для нераспознанного пути,
изменения общих входов либо новой версии средства или правил анализа сценарий
выбирает полный обязательный набор проверок и объясняет причину в отчёте.

## Границы

- Не выводи направление зависимости только из расположения файлов.
- Не заменяй профильную проверку фактом достижимости вершины.
- Не помечай всю достижимую область как требующую правки без смысловой проверки.
- Не обрезай обход первым уровнем и не останавливай его на цикле раньше
  достижения неподвижной точки.
- Не скрывай несопоставленный путь общим узлом без осмысленной ответственности.
- Не завершай задачу при незакрытой затронутой вершине.
- Не подменяй профильную проверку успешным результатом детерминированной
  команды.
- Не запускай команду из строки оболочки и не передавай в отчёт значения
  переменных среды или полный вывод проверки.

## Результат

Назови изменённые вершины и аспекты, все затронутые вершины, путь влияния до
каждой из них, применённые профильные проверки и итог каждой проверки. Отдельно
назови пробелы графа, требуемые решения человека и блокеры.
