# Договор графа влияния проекта

`project-impact.json` — единый машинно-проверяемый договор о направлениях
возможного влияния между частями проекта. Ребро `from → to` означает: изменение
вершины `from` в одном из перечисленных аспектов требует проверить вершину `to`.

Граф описывает возможность влияния, а не приказ изменить все достижимые
артефакты. Смысловой вывод остаётся за профильной проверкой.

## Структура

Корневой объект содержит только поля:

- `schema_version` — целое число `1`
- `graph` — настройки договора
- `nodes` — непустой список вершин
- `edges` — список направленных рёбер

Объект `graph` содержит:

- `name` — непустое имя проекта
- `description` — назначение конкретного графа
- `default_facet` — аспект по умолчанию
- `unmapped_paths` — `block` или `warn`
- `ignore` — шаблоны путей, не входящих в договор

Каждая вершина содержит:

- `id` — устойчивый идентификатор из строчных латинских букв, цифр и дефисов
- `title` — понятное название части проекта
- `kind` — тип из списка ниже
- `paths` — непустой список путей или шаблонов от корня проекта
- `checks` — непустой список профильных навыков или проверок
- `review_stages` — необязательные области полной проверки

Допустимые типы вершин:

- `concept`
- `knowledge`
- `requirements`
- `architecture`
- `decision`
- `implementation`
- `test`
- `documentation`
- `operation`
- `process`
- `configuration`
- `delivery`
- `other`

Каждое ребро содержит:

- `from` и `to` — существующие вершины
- `relation` — тип смысловой зависимости
- `facets` — непустой список аспектов, при которых ребро действует
- `rationale` — проверяемое объяснение направления

Допустимые отношения:

- `constrains`
- `informs`
- `refines`
- `realizes`
- `verifies`
- `documents`
- `configures`
- `packages`
- `operates`
- `governs`

## Аспекты изменения

- `semantic` — изменён смысл, обязательство или вывод
- `interface` — изменён внешний или внутренний договор взаимодействия
- `data` — изменены данные, схема, происхождение или жизненный цикл
- `quality` — изменено требуемое или обеспечиваемое свойство качества
- `security` — изменена граница доверия, угроза или мера защиты
- `reliability` — изменено поведение при отказе или эксплуатации
- `operation` — изменены развёртывание, сопровождение или рабочая процедура
- `structure` — изменены размещение, состав или навигация без заявленного
  изменения смысла
- `documentation` — изменено пользовательское или справочное представление
- `any` — ребро действует при любом аспекте

`any` разрешён только в `facets` ребра. Изменение получает конкретный аспект.

## Сопоставление путей

Пути записываются относительно корня проекта с разделителем `/`. Разрешены
шаблоны `*`, `?`, `[]` и `**`. Один путь может принадлежать нескольким вершинам,
если артефакт действительно выполняет несколько обязанностей.

Режим `unmapped_paths: block` не допускает завершить работу с новым или
изменённым путём вне графа. Режим `warn` разрешён только как явно принятое
временное состояние проекта и должен оставлять ограничение в результате.

## Обход и циклы

Анализатор обходит пары «вершина, аспект» в ширину. Он применяет ребро, если
аспект входит в `facets` либо список содержит `any`. Каждая пара обрабатывается
один раз, поэтому цикл завершается в неподвижной точке. Результат содержит
кратчайший найденный путь до каждой затронутой пары.

Если профильная правка достигнутой вершины создаёт аспект, которого не было у
неё во входном наборе, эта пара добавляется как новый вход. Обход повторяется
для объединённого набора до тех пор, пока профильные проверки не перестанут
порождать новые пары.

## Завершённость

Для каждой затронутой вершины обязателен один итог:

- `updated`
- `verified_no_impact`
- `human_decision`
- `blocked`

Команда `assess` завершается успешно, только если все затронутые вершины имеют
итог `updated` или `verified_no_impact`. Остальные итоги сохраняют точный
блокер, но не разрешают завершить проектную задачу.
