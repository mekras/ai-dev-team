# Навык: сообщения коммитов

## Назначение

Навык помогает подготовить или проверить сообщение коммита по одной схеме,
которую проект выбрал при настройке.

## Когда применять

Применяй навык, если пользователь просит:

- подготовить или проверить сообщение коммита;
- привести сообщения коммитов к правилам проекта;
- выполнить коммит и для него нужно составить сообщение.

При выполнении коммита применяй навык до команды `git commit`, если проект
закрепил схему сообщений коммитов.

Не применяй навык для выпуска версии, журнала изменений, описания запроса на
слияние или выбора общей политики Git без работы с сообщением коммита.

## Обязательный порядок

1. Найди рабочее правило в применимых инструкциях проекта. Сверь его со
   `setup.commit_messages` в `.ai-dev-team-state.yml`, если файл существует.
2. Если источники расходятся, остановись и запроси решение владельца проекта.
   Если схема ещё не выбрана, при настройке проекта передай выбор в `ait-setup`,
   а в разовой задаче не выбирай схему молча.
3. Прочитай `references/schemes.md` для выбранной схемы. Проектное правило имеет
   приоритет над необязательными рекомендациями справки, но не над синтаксисом
   выбранной внешней спецификации.
4. Проверь фактический состав коммита по индексу Git. Если индекс пуст, сообщи
   об этом. Если в нём смешаны независимые изменения, предупреди пользователя,
   прежде чем формулировать одно обобщающее сообщение.
5. Сформулируй заголовок по наблюдаемому изменению. Не добавляй номер задачи,
   область, несовместимое изменение или намерение, которых нет во входных данных
   или правилах проекта.
6. Добавь тело и служебные строки только когда они объясняют причину,
   последствия, несовместимость или связь, неясные из заголовка.
7. Проверь сообщение по синтаксису выбранной схемы, языку проекта и локальным
   ограничениям. Верни готовое сообщение и кратко назови применённую схему.

## Источники выбора

Поддерживаются три значения `setup.commit_messages.scheme`:

- `conventional-commits`;
- `gitmoji`;
- `pro-git`.

Для `gitmoji` проект дополнительно закрепляет
`setup.commit_messages.emoji_format`: `unicode` или `shortcode`.

Рабочее правило со схемой должно быть доступно агенту в обычной задаче, например
в `AGENTS.md`. Файл состояния хранит параметр повторной настройки и не заменяет
рабочую инструкцию.

## Границы

- Не выполняй `git commit`, `push`, переписывание истории или исправление
  прежних сообщений без явного разрешения пользователя и правил проекта.
- Не смешивай схемы и не добавляй Gitmoji к Conventional Commits, если проект
  явно не выбрал отдельный гибридный профиль.
- Не исправляй содержимое индекса Git ради удобного сообщения.
- Не выдавай рекомендуемую длину строки за синтаксическое требование внешней
  спецификации.

## Проверка результата

Результат пригоден, если сообщение описывает фактический состав индекса,
соответствует одной выбранной схеме и не вводит неподтверждённых последствий.
