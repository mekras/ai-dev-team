# Подключение ai-dev-team

Проект использует `ai-dev-team`.

## Корень навыков ai-dev-team

Используй первый доступный корень навыков с обязательными файлами:

- `.agents/skills`;
- `.claude/skills`.

Корень подходит, если в нём есть файлы:

- `ait-routing/SKILL.md`;
- `ait-routing/references/skill-index.md`;
- `ait-setup/SKILL.md`.

Если ни один корень не подходит, остановись и сообщи о блокере.

## Маршрут задачи

Перед предметной работой открой `ait-routing/SKILL.md` из выбранного корня
навыков, выбери режим и покажи маршрут:

```text
Режим менеджера: лёгкий|полный.
Причина: ...
Маршрут: понятные человеку этапы; технические имена — в скобках, если нужны для
действия или проверки.
```

Если маршрут выбирает навык из индекса `ait-routing/references/skill-index.md`,
до исполнения открой соответствующий `<skill>/SKILL.md` из выбранного корня
навыков и применяй его правила. Одного упоминания навыка в маршруте
недостаточно. Если выбранный навык отсутствует в корне навыков, остановись и
сообщи о блокере.

Для запросов вида «Настрой проект», «Перенастрой проект», «Начни новый проект»,
«Инициализируй проект», «Подготовь новый репозиторий» и близких по смыслу
запросов обязательно применяй `ait-setup/SKILL.md` из выбранного корня навыков.

## Передача результата

Не называй результат принятым по факту завершения ответа, команды или тестов.
Передай человеку артефакт, критерии приёмки, результаты выполненных проверок,
пропуски, ограничения и остаточные риски. Статус `готов к приёмке` означает, что
результат можно проверить; статус `принят` допустим только после явного решения
человека. Провал обязательной проверки означает `нужна доработка`, а внешний
блокер — `заблокирован`.

## Переносимость правил

Храни общий смысл проектного правила, роли, навыка или контекста в переносимом
источнике, который APM может развернуть для поддерживаемых клиентов. Не веди
независимые смысловые копии одного правила отдельно для Claude и Codex.

Клиентский адаптер допустим только для возможности, которую нельзя выразить
переносимым примитивом. Зафиксируй недостающую возможность и её проверку,
затронутые клиенты, переносимый источник общего смысла, границу адаптера и
условие его пересмотра или удаления. Удобство одного клиента и привычка автора
не являются достаточным основанием для исключения.
